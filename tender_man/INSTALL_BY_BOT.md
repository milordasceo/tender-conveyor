# Установка Тэндер Мэна ботом

Для пустого бота на новом аккаунте, который сам становится Тэндер Мэном (главой команды), а затем создаёт остальные звенья. Все значения — из `tender_man/bot.yaml`. Кто такой Тэндер Мэн — `tender_man/README.md`. Общий порядок bootstrap — корневой `README.md`.

Правила:

- шаги по порядку; следующий — только после контрольной точки (КТ);
- реальные agent id, адреса почты, id папок Drive и страниц Notion в репозиторий и отчёты не писать;
- конфиг rclone (`~/.config/rclone/rclone.conf`) не читать, не показывать, не копировать, не менять;
- рутины (свои и звеньев) — только на шаге 7, пункт e, каждая с подтверждением владельца на карточке;
- шаги владельца всех звеньев — на шаге 7, по одному, после отчётов о готовности;
- в Notion и на Диске Тэндер Мэн только читает.

## 1. Прочитать манифест

```bash
rm -rf /tmp/tender-conveyor && git clone https://github.com/milordasceo/tender-conveyor.git /tmp/tender-conveyor
```

Прочитать `tender_man/bot.yaml`, `tender_man/bot/prompt.md`, `tender_man/prompts/morning_report_prompt.md`, `tender_man/prompts/evening_report_prompt.md`, `tender_man/README.md`, корневой `README.md` (раздел «Bootstrap»).

КТ: известны имя, промт, шесть плейсхолдеров (`bot.placeholders`), две рутины отчётов (план), коннектор Notion (необязателен), `first_setup`, `verification`.

## 2. Стать Тэндер Мэном

1. Имя, заголовок, описание — из `bot`: `bot.name` = Тэндер Мэн, `bot.title`, `bot.description`.
2. Системный промт — весь файл `bot.prompt_file` (`tender_man/bot/prompt.md`), без правок по смыслу.
3. Плейсхолдеры звеньев (`<id Кузнеца>`, `<id Фатимы>`, `<id Черри Пикера>`, `<id Очкарика>`, `<id Сисадмина>`) пока оставить: этих ботов ещё нет. Заменить на шаге 6.
4. `<id Тэндер Мэна>` в своём промте — заменить своим agent id. Свой id записать: его подставляют во все звенья.
5. Рутины отчётов не создавать (шаг 7, пункт e).

КТ: бот «Тэндер Мэн» с промтом из репозитория; последняя строка промта — ссылка на папку `tender_man/`; свой id известен.

## 3. Состояние бокса

Корневой `README.md`, шаг 0: свежий box (нет `gosplan:`) или общий (`rclone lsd gosplan:Госзакупки` отвечает). На общем box ничего не пересоздавать. Прежние боты конвейера — владелец останавливает их рутины до запуска новых.

КТ: записано: свежий или общий box; прежние боты остановлены или их нет.

## 4. Создать звенья

Строго в порядке корневого `README.md` (шаги 2–6), каждое — по его `INSTALL_BY_BOT.md`, в каждое подставить свой id вместо `<id Тэндер Мэна>`:

1. Кузнец — `kuznets/INSTALL_BY_BOT.md` (на свежем box создаёт rclone remote `gosplan:`; вход владельца — шаг 7, пункт a);
2. Фатима — `fatima/INSTALL_BY_BOT.md`;
3. Черри Пикер — `cherry_picker/INSTALL_BY_BOT.md`;
4. Очкарик — `ochkarik/INSTALL_BY_BOT.md`;
5. Сисадмин — `sysadmin/INSTALL_BY_BOT.md` (Notion — шаг 7, пункт c).

Звено делает всё, что может без владельца, и владельца не ждёт: его шаги владельца проводятся на шаге 7. Рутины звенья при установке не создают (шаг 7, пункт e). Загрузчик на Windows-ПК — тоже шаг 7 (пункт b).

КТ: пять ботов созданы; id каждого записан (только в промты и свой чеклист, не в репозиторий).

## 5. Этап «первичная настройка»: отчёты о готовности

Порядок этапа — `first_setup` в `bot.yaml`; корневой `README.md`, шаг 7.

1. Последний шаг установки каждого звена — сообщение тебе: «Готов: <имя звена>, мой id <id>, от владельца нужно: <список>» (список — невыполненные `owner_steps` и обязательные `connectors` из его папки, или «ничего»).
2. Чеклист (держать у себя, в репозиторий не писать):

   | звено | отчёт | id совпал | от владельца нужно |
   |---|---|---|---|
   | Кузнец | | | |
   | Фатима | | | |
   | Черри Пикер | | | |
   | Очкарик | | | |
   | Сисадмин | | | |

3. Id из отчёта сверить с id, полученным при создании. Не совпал — спросить звено, разобраться до шага 6.
4. Звено молчит дольше 30 минут после создания — SendToAgent: «Пришли отчёт о готовности по последнему шагу INSTALL_BY_BOT». После второго напоминания молчит — сказать владельцу.

КТ: пять отчётов получены; id совпадают.

## 6. Связать id

1. В свой промт — id всех пяти звеньев.
2. Каждому звену — одно сообщение с реальными id ботов из его `bot.placeholders` (Кузнецу — ещё `<id Фатимы>`): «Id команды: Тэндер Мэн <id>, Кузнец <id>, … Замени плейсхолдеры `<id …>` в своём промте, промтах рутин и памяти; ответь «Id заменены» и результатом `rg -n "<id "`».
3. Ждать пять подтверждений. `<id Скрипты и интеграции>` у Кузнеца — такого бота в репозитории нет; плейсхолдер оставить, вопрос владельцу — шаг 7, пункт d.
4. Проверка связи (`verification`, шаг 2): «Проверка связи от Тэндер Мэна, ответь «на связи» и одной строкой — что сейчас во входной папке» — пять ответов (до пункта a входные папки могут быть недоступны — это нормально).

КТ: в твоём промте нет `<id `; пять подтверждений «Id заменены»; пять ответов на проверку связи.

## 7. Чеклист владельца

Свести списки из отчётов в один чеклист и вести владельца **по одному пункту**: сказать, что нужно и зачем (`say` из `owner_steps` звена), дождаться подтверждения и КТ, только потом следующий. Мелкие да/нет (прежние боты остановлены, `old_registry`, разрешения `test_folder`/`test_card`) — одной карточкой-вопросом перед пунктом a; ответы передать звеньям. Пункт не нужен (например, доступ уже есть) — показать владельцу и закрыть его словом.

a. **Вход rclone (Кузнец).** Команда Кузнецу: свежий box — сначала `oauth_client` (владелец присылает секреты Кузнецу как секреты), затем `rclone config create gosplan …` (`kuznets/bot.yaml` → `owner_steps.rclone_authorize`); remote есть, но 401/`invalid_grant` — `rclone config reconnect gosplan:`. Кузнец запускает в фоне, открывает ссылку входа в браузере бокса и передаёт рабочий стол владельцу. Владельцу: войти аккаунтом Google, **владеющим папкой «Госзакупки»**, не аккаунтом Google Cloud Console; OAuth-клиент должен быть In production (`kuznets/SETUP.md`, раздел 6), иначе вход истечёт через 7 дней. Затем — команда всем звеньям доделать шаги Диска и `verification` своей установки. КТ: Кузнец — `rclone lsd gosplan:Госзакупки` видит «Сток» и «Бланки»; все пять подтвердили доступ к Диску и `verification`.

b. **Загрузчик.** Владельцу — `fatima/stock_docs_fetcher/README.md`: `INSTALL.bat`, затем `STATUS.bat`. Проверять Google Drive for desktop отдельно не нужно. Вопросы — Кузнецу (он сопровождает загрузчик). КТ: `STATUS.bat` показывает, что загрузчик работает; Кузнец или Фатима подтверждает, что папки уходят из «Сток» в «Бланки».

c. **Коннекторы.** Только из `connectors` в `bot.yaml`: Notion — Сисадмину обязательно (`sysadmin/bot.yaml` → `owner_steps.connect_notion`), тебе по желанию (`owner_steps.connect_notion`; после входа — `search` «К рассмотрению», `fetch` базы «Тендеры», только чтение). Google Drive — Кузнецу (`required: true`, тот же аккаунт, что владеет «Госзакупки»), остальным не нужен. Gmail ни одно звено не требует — не подключать без слова владельца. КТ: Сисадмин доделал шаг Notion своей установки и подтвердил; у тебя Notion читается или записано «без Notion».

d. **Роли.** Карточки-вопросы владельцу, по одной на звено: имя, что делает, вход → выход, кому отчитывается — из `bot.description`, `order_hint`, `teammates` его `bot.yaml`. Варианты: «верно» / «поправить». Поправку передать звену как «команда владельца», дождаться «Принято». Последней карточкой — `<id Скрипты и интеграции>`: создать бота или убрать. КТ: пять карточек подтверждены.

e. **Рутины.** По очереди каждому звену: «Создай свои рутины из `routines` своего `bot.yaml`, `CRON_TZ=Asia/Novosibirsk`, время — подтверждённое владельцем; владелец одобрит на карточке; ответь «Рутина <имя> создана, подтверждена»». Владельцу — сказать, какая карточка сейчас появится. Свои две рутины (`routines`) создать так же, с карточкой владельца. Вести список рутин и отмечать подтверждённые; Кузнецу почасовую проверку добора — только после развёртывания добора. КТ: все рутины из корневого `README.md` (таблица шага 7.3) созданы и подтверждены.

f. **Тестовый прогон.** По очереди командовать звеньям прогон на живых данных, без тестовых папок: Кузнец (статус добора / скан) → загрузчик («Сток» → «Бланки», проверяет Кузнец) → Фатима → Черри Пикер → Очкарик → Сисадмин (карточка в Notion, папка в «CRM»). Каждое отвечает одной строкой: что взяло, что выдало, ошибки. Затем своя `verification`: Notion (если подключён) и тестовый утренний отчёт владельцу с пометкой «тест». КТ: шесть результатов (пять звеньев и твой отчёт); ошибки разобраны или вынесены владельцу.

Часовой пояс рутин — всегда Asia/Novosibirsk; часовой пояс бокса Grok Bot на расписание не влияет и для расчёта не используется.

## 8. Конвейер запущен: итоговая сводка владельцу

Только после шагов 5–7 целиком. Одно сообщение:

- Тэндер Мэн создан, промт вставлен; свежий или общий box;
- звенья: созданы, отчитались, id разосланы; какие плейсхолдеры остались (и почему);
- rclone `gosplan:` и раскладка Диска, загрузчик на Windows-ПК;
- коннекторы: Notion у Сисадмина и у тебя (подключён / нет);
- роли: подтверждены / что поправлено;
- рутины: какие созданы и подтверждены;
- тестовый прогон: результат по каждому звену;
- что ещё ждёт владельца (если есть).

Последняя строка: «Конвейер запущен» — или «Конвейер не запущен: <какой пункт открыт>». До этой строки конвейер не считается запущенным.
