# Кузнец

Бот Grok Bot. Первое звено конвейера тендеров (госзакупки).

## Файлы папки

| файл | для кого | что |
|---|---|---|
| `bot.yaml` | бот-установщик | машинный манифест: бот, промт, рутина, файлы, зависимости, секреты, шаги владельца, проверка, первый прогон |
| `INSTALL_BY_BOT.md` | бот-установщик | пошаговая установка с контрольными точками и отчётом владельцу |

## Кто такой Кузнец

- Первое звено. Сверху ничего не получает: сам находит тендеры в API gosplan.info.
- Кладёт найденные тендеры папками в Google Drive «Госзакупки/Сток».
- Из «Сток» папки забирает загрузчик документов (`fatima/stock_docs_fetcher`, работает на windows-пк владельца): качает документы по `tender.json` и переносит папку в «Госзакупки/Бланки». Поэтому `tender.json` в каждой папке обязателен.
- Фатима берёт тендеры только из «Бланков». В «Сток» она не заходит.
- Отчитывается Тэндер Мэну — главе команды конвейера.
- Правки кода заказывает боту «Скрипты и интеграции».
- Работает на своём боксе Grok Bot, не на компьютере владельца.
- Второе дело — сопровождать сканер и инструменты конвейера. Загрузчик `fatima/stock_docs_fetcher` собран и принят Кузнецом вместе с ботом «Скрипты и интеграции». Живёт в папке Фатимы, сопровождает Кузнец: правки в нём — через Кузнеца. Зеркало на боксе — `/home/box/gosplan/scripts/stock_docs_fetcher/`.
- Другим ботам Кузнец даёт инструменты: скрипты, загрузчики, общий remote `gosplan:`. Как им работать, не пишет. Роль, промт и рутины звена описывает само звено в своей папке.

```
gosplan.info API ──► Кузнец ──► «Госзакупки/Сток/<номер>/»
                       │                 │
                       │                 ▼  загрузчик fatima/stock_docs_fetcher
                       │                    (windows-пк владельца; сопровождает Кузнец)
                       │        «Госзакупки/Бланки/<номер>/» ──► Фатима
                       │
                       ├── отчёт ──► Тэндер Мэн (срочное: «владельцу:»)
                       └── заказ кода ──► Скрипты и интеграции
```

Устройство других звеньев здесь не описано. Его описывают их папки.

## Что Кузнец НЕ делает

- не скачивает документы тендеров — это загрузчик `fatima/stock_docs_fetcher` на windows-пк владельца (Кузнец его только сопровождает);
- не разбирает тендеры, не считает цены и маржу;
- не пишет заявки и сопроводительные документы;
- не отправляет письма, посты, платежи;
- не трогает руками папки в «Сток» и реестр — только скриптом;
- не пишет владельцу напрямую — только через Тэндер Мэна;
- не инструктирует другие звенья и не пишет их промты и рутины — только даёт инструменты;
- не меняет параметры поиска без команды владельца или договорённости со Тэндер Мэном;
- не создаёт себе рутины — их создаёт владелец после проверки;
- не запускает сканер вручную без `--limit`: очередь выгружает добор.

## Выход

- папка на каждый новый тендер: `gosplan:Госзакупки/Сток/<номер>/` с `tender.md` и `tender.json` (формат — `FORMAT.md`);
- тендеры вне города тоже выгружаются, только с пометкой `город: вне города`;

- одно сообщение Тэндер Мэну, если есть результат или проблема.

## Как Кузнец работает: шаг за шагом

Один прогон = одна команда:

```bash
cd /home/box/gosplan/scripts && ../.venv/bin/python gosplan_scanner.py -c config.novosibirsk.yaml --remote 'gosplan:Госзакупки/Сток'
```

В работе сканер вызывается только через `gosplan_drain.py` и всегда с `--limit 1` (раздел «Добор очереди»).

Что делает сканер внутри:

1. Читает конфиг и флаги CLI. Флаг важнее конфига.
2. Открывает реестр в `state_dir`. Имя файла — sha1 строки приёмника `gosplan:Госзакупки/Сток`, первые 12 знаков.
3. Очередь `pending` в реестре не пуста → поиска нет, сразу шаг 7 (добор).
4. Считает дату публикации «с» (`since: auto`):
   - `last_completed_at` пуст → без фильтра даты (первый прогон берёт всё подходящее);
   - иначе — дата `last_completed_at` по Москве минус 1 день.
5. Листает списки 44-ФЗ и 223-ФЗ по фильтрам, по 100 на страницу. Повторно фильтрует на клиенте: тип закупки, сроки, дата.
6. Новые = найденные минус номера из реестра. Кладёт их в `pending`, сортирует по дате публикации и номеру.
7. Добор очереди. Один раз `rclone lsf` по «Сток». Для каждого номера:
   1. запрос детали в API;
   2. проверка города поставки → `в городе` / `вне города` / `нет данных`;
   3. сборка `tender.md` и `tender.json` во временной папке на боксе;
   4. папка с таким номером уже есть в «Сток» → в реестр как `exported` без копирования;
   5. иначе `rclone copy` в `Сток/<номер>`;
   6. код 0 → номер в реестр, из очереди долой. Сбой → номер остаётся в очереди.
8. Очередь пуста → в реестр `last_completed_at`. Код выхода 0.
9. Очередь не пуста → код выхода 3. Следующий прогон добирает без нового поиска.
10. Пишет `run_report.json`, на stdout три строки: `найдено`, `новых`, `выгружено`.

## Ежедневный цикл

Две рутины и один фоновый процесс.

| что | когда | команда | делает |
|---|---|---|---|
| утренний скан | `0 7 * * *` | `gosplan_drain.py daily` | очередь пуста → поиск + 1 выгрузка, остаток — в добор. Очередь не пуста или добор работает → только проверяет, что добор жив |
| добор | постоянно, пока очередь не пуста | `drain_start.sh` → `gosplan_drain.py run` | по одной закупке примерно раз в 30 с |
| почасовая проверка | `0 * * * *` | `gosplan_drain.py status` | добор мёртв и очередь не пуста → перезапуск. Сообщение только при проблеме или когда «Сток» догружен |

Очередь не выгружается одной длинной пачкой. Новый поиск — только когда очередь пуста.

Без реестра первый поиск берёт все текущие подходящие тендеры. С перенесённым реестром (515 в очереди на 29.10.2026) первым делом идёт добор: ~4–5 часов при 30 с на закупку. Первый поиск — утром после опустошения очереди.

## Добор очереди

`scripts/gosplan_drain.py`, подкоманды:

- `run` — цикл. Перед каждым шагом читает реестр: очередь пуста → выход 0, сканер не вызывается (с пустой очередью `--limit 1` начал бы новый поиск). Иначе — `gosplan_scanner.py -c config.novosibirsk.yaml --remote 'gosplan:Госзакупки/Сток' --limit 1`;
- `start` — запустить `run` отсоединённым процессом, если он не работает и очередь не пуста. `drain_start.sh` — обёртка над `start`;
- `status` — json: `drain_running`, `pending`, `exported_total`, `exported_last_hour`, `drain_status`, `run_report`;
- `daily` — утренний прогон (таблица выше).

Почему `--limit 1` безопасен: при непустой очереди сканер пропускает поиск («pending не пуст — поиск пропущен, сначала добор»), берёт закупки из очереди по порядку и останавливается после первой выгруженной. Папки, которые уже есть в «Сток», в лимит не входят: номер уходит в реестр без копирования, сканер берёт следующую. Проверено на копии реестра.

Шаг цикла:

| итог шага | что дальше |
|---|---|
| код 3, очередь сдвинулась | пауза до 30 с от старта шага (`DRAIN_INTERVAL`) |
| код 0, очередь пуста | `state: done`, выход |
| код не 0/3 или очередь не сдвинулась | `last_error`, пауза 300 с (`DRAIN_BACKOFF`), дальше |
| SIGTERM / Ctrl+C | `state: stopped`, выход |

Блокировка: `state/kuznets_run.lock` (`flock`). Её держит `run` всё время работы и `daily` на время поиска. Второй добор не стартует. Утренний поиск не идёт, пока работает добор.

Файлы: `state/drain_status.json` (`pid`, `state`, `started_at`, `last_run_at`, `last_exit`, `uploaded_total`, `pending_left`, `last_progress_at`, `last_error`, `interval`), `logs/drain.log` (шаги добора и stderr сканера).

Автозапуск: systemd (`systemctl --user` — нет шины) и cron на боксе нет, PID 1 — `tini`. Добор — процесс в новой сессии (`start_new_session`), переживает конец команды. После перезагрузки бокса его поднимает почасовая рутина (`drain_start.sh` идемпотентен).

## Нет дублей

- Реестр на боксе, не в «Сток»: Фатима уносит папки из «Сток», по папкам дубли не отследить.
- Номер в реестре только после успешной загрузки.
- Перед загрузкой — `rclone lsf`: папка уже в «Сток» → не копировать.
- Повторный прогон того же дня не создаёт папок второй раз.
- Реестр живёт на боксе. Перенесённая копия — в `kuznets/state/`. Новый бокс с пустым реестром на тот же «Сток» выгрузил бы заново то, что Фатима уже унесла. Поэтому реестр кладётся до первого запуска: `INSTALL_BY_BOT.md`, шаг 7.

## Лимит API

- Не больше 10 запросов в минуту. Базовый интервал 10 с.
- HTTP 429: интервал ×1.5 (потолок 20 с) до конца прогона; пауза по `Retry-After`; до 4 повторов на запрос.
- Слот общий для всех процессов: `state_dir/gosplan_api.slot`, блокировка `flock`. Два сканера одновременно не превышают лимит.
- Сетевой обрыв на странице списка — повтор через 10/20/30 с.

## Особые случаи

| ситуация | признак | что делает Кузнец |
|---|---|---|
| всё выгружено | код 0, `pending_left: 0` | добор: `state: done`. Почасовая рутина один раз пишет Тэндер Мэну «сток догружен: N тендеров» |
| очередь не пуста | код 3, `pending: осталось N` | норма для добора. Утренний скан не ищет, только проверяет добор. Сканер без `--limit` вручную не запускать |
| добор не работает | `status`: `drain_running: false`, `pending` > 0 | почасовая рутина запускает `drain_start.sh`. Снова упал — отчёт «добор не держится» |
| нет движения час | `exported_last_hour: 0` при работающем доборе | отчёт Тэндер Мэну с `last_error` |
| второй запуск | блокировка занята | `start`/`run` — «уже работает», выход 0; `daily` — без поиска или код 75 |
| ошибка конфига | код 2 | отчёт Тэндер Мэну с текстом ошибки; параметры не менялись самовольно — проверить последнюю правку |
| другой код | код ≠ 0, 2, 3 | отчёт: код и строка из stderr |
| частые 429 | `http_429` > 0, «интервал запросов повышен» | норма для теста. Прогон длиннее. Много дней подряд код 3 — «владельцу:» про прод-ключ |
| API недоступен | ошибки сети/HTTP весь прогон | отчёт с «владельцу:» |
| ошибка детали одного тендера | строка в логе, номер остаётся в очереди | ничего; повтор в следующем прогоне. 5 сбоев подряд — стоп прогона, отчёт |
| rclone 401 / `invalid_grant` / `token expired` | `rclone_failures` > 0, `last_error`, текст в логе | добор уходит в паузы по 300 с, очередь цела. Отчёт с «владельцу:»: нужен повторный вход rclone аккаунтом, владеющим «Госзакупки». Приложение опубликовано (In production), 7-дневного истечения нет: значит, доступ отозван, сменён пароль или вернули режим Testing — проверить consent screen |
| `rclone lsf` не прошёл | «rclone lsf не удался», код 3 | выгрузка не начата, очередь цела. Отчёт |
| «Сток» не найден | `directory not found` у `lsf` | норма: `rclone copy` создаст папку |
| папка уже в «Сток» | «уже есть на remote» | номер в реестр без копирования |
| найдено 0 | `найдено: 0`, код 0 | молчит |

## Смена параметров

1. Основание: команда владельца или договорённость со Тэндер Мэном. Другие звенья пишут Тэндер Мэну, не Кузнецу напрямую.
2. Кузнец правит yaml-конфиг. Промт рутины не трогает: рутина берёт всё из конфига.
3. Для `--kind`: коды берутся из блока `purchase_kinds` и перекрывают `filters.purchase_types`.
4. Проверка: `--dry-run`. В stderr видны URL запросов с новыми фильтрами. Код 0.
5. Отчёт Тэндер Мэну: было → стало, с какой даты действует.
6. Расширение фильтров не тянет старые тендеры: дата «с» берётся от последнего прогона. Нужны старые — разовый прогон с `--since ДАТА`, по согласованию.

## Известные проблемы

- Тестовый API часто отвечает 429. Прод-ключ может помочь.

- zakupki.gov.ru с бокса недоступен (гео). Выгрузке не мешает: пишутся только ссылки.
