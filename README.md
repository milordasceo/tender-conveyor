# tender-conveyor

Конвейер тендеров (госзакупки, Новосибирск) для Grok Bot. Оригинал: https://github.com/milordasceo/gosplan-conveyor.

Этот файл — точка входа. Его читает пустой бот на новом аккаунте. Пустой бот становится Тэндер Мэном (глава команды) и создаёт остальных ботов по папкам этого репозитория.

## Что это

- Каждое звено — отдельный бот Grok Bot. У звена своя папка.
- В папке звена всё для пересоздания: `bot.yaml`, промты, рутины, скрипты, установка, проверка.
- Формат папки — [TEMPLATE_LINK.md](TEMPLATE_LINK.md). Схема манифеста — [SCHEMA.md](SCHEMA.md).
- Данные звеньев — на Google Drive в папке «Госзакупки». Доступ с бокса — rclone remote `gosplan:`.
- Звенья связаны папками Drive. Сообщения — только Тэндер Мэну через SendToAgent. Владельцу пишет только Тэндер Мэн.
- Секретов, адресов почты, id ботов и id папок Drive в репозитории нет.

## Схема конвейера

```
                              Тэндер Мэн  (глава: владелец ⇄ Тэндер Мэн ⇄ все звенья)
                                   │ отчёты, команды, эскалации
 ┌─────────────────────────────────┴───────────────────────────────────────────────────┐
 API gosplan.info → Кузнец → «Сток» → stock_docs_fetcher (Windows-ПК владельца) → «Бланки»
   → Фатима → «Цены/Новосибирск/<категория>» → Черри Пикер → «К расчёту»
   → Очкарик → «К рассмотрению» (прибыль от 9 000 ₽) | «Нерентабельно»
   → Сисадмин → Notion «Тендеры» (страница «К рассмотрению») + папка → «CRM»
```

## Bootstrap: пустой бот → Тэндер Мэн → звенья → первичная настройка

Правила на весь bootstrap:

- шаги по порядку; следующий — после контрольной точки (КТ) текущего;
- `<id …>` в промтах заменять реальными agent id; бота ещё нет — оставить плейсхолдер. Реальные id всех ботов рассылает Тэндер Мэн на шаге 7.2;
- при создании звено делает всё, что может без владельца, и не ждёт его: шаги владельца из его папки (`owner_steps`, обязательные `connectors`) собирает Тэндер Мэн и проводит с владельцем на шаге 7. Шаг установки, который упёрся в шаг владельца (вход rclone, Notion), звено доделывает сразу после нужного пункта 7.3 вместе со своей `verification` и подтверждает Тэндер Мэну;
- рутины всех звеньев — только на шаге 7.3, пункт e, после `verification` звена;
- секреты — только как секреты, не в чат, не в репозиторий, не в отчёты.

### 0. Состояние бокса

```bash
git clone https://github.com/milordasceo/tender-conveyor   # или git pull --rebase в существующей копии
rclone listremotes          # есть ли gosplan:
rclone lsd gosplan:Госзакупки
ls /home/box/gosplan        # следы прежнего Кузнеца
```

- **Свежий box**: нет rclone или нет `gosplan:`. Remote создаёт Кузнец (шаг 2) по `kuznets/INSTALL_BY_BOT.md`; вход владельца в Google — шаг 7.3, пункт a.
- **Общий box**: `gosplan:` уже есть, `rclone lsd gosplan:Госзакупки` отвечает без 401/`invalid_grant`. Remote не пересоздавать, конфиг rclone не читать и не трогать. `/home/box/gosplan` и его `scripts/state`, `.env` не затирать. Кузнеца всё равно создать; шаги rclone и OAuth в его установке пропустить, если КТ его шага 6 уже выполнена. 401/`invalid_grant` — повторный вход rclone (шаг 7.3, пункт a).
- Есть прежние боты конвейера — владелец останавливает их рутины и фоновую выгрузку Кузнеца до запуска новых. Два Кузнеца на один «Сток» дают дубли. Два главы шлют отчёты дважды.

### 1. Стать Тэндер Мэном

1. Идти по [tender_man/INSTALL_BY_BOT.md](tender_man/INSTALL_BY_BOT.md); значения — из [tender_man/bot.yaml](tender_man/bot.yaml), описание — [tender_man/README.md](tender_man/README.md).
2. Имя, заголовок, описание — из `bot`. Системный промт — весь `tender_man/bot/prompt.md`.
3. Плейсхолдеры звеньев пока оставить. Свой id записать: он `<id Тэндер Мэна>` во всех звеньях.
4. Рутины отчётов пока не создавать (шаг 7.3, пункт e).

КТ: бот «Тэндер Мэн» с промтом из репозитория; свой id известен.

### 2. Кузнец

По [kuznets/INSTALL_BY_BOT.md](kuznets/INSTALL_BY_BOT.md). Подставить `<id Тэндер Мэна>`. `<id Фатимы>` — на шаге 7.2.

- Свежий box: файлы, зависимости, `--dry-run`. OAuth-клиент и вход rclone — шаги владельца (7.3, пункт a); раскладка «Сток»/«Бланки», реестр, проверка и добор — сразу после пункта a.
- Общий box: проверить раскладку, ничего не пересоздавать.
- Реестр выгрузки — из `kuznets/state/`, не затирать существующий на боксе.

КТ: бот «Кузнец» создан, файлы и зависимости на месте; отчёт о готовности Тэндер Мэну отправлен.

Добор (`gosplan_drain.py`, `drain_start.sh`) в репо есть, но на текущем общем box в `/home/box/gosplan/scripts` не развёрнут. На общем box развернуть его по `kuznets/INSTALL_BY_BOT.md` (шаг 4) до создания рутин Кузнеца.

### 7. Этап: первичная настройка после создания ботов

Ведёт Тэндер Мэн. Начинается, когда созданы все пять звеньев. Порядок — по `tender_man/bot.yaml` → `first_setup`, подробно — `tender_man/INSTALL_BY_BOT.md`, шаги 5–8.

#### 7.1. Отчёты о готовности

1. Последний шаг установки каждого звена — сообщение Тэндер Мэну через SendToAgent:

   «Готов: <имя звена>, мой id <id>, от владельца нужно: <список>»

   Список — шаги владельца из папки звена, которые ещё не сделаны: ключи `owner_steps` и обязательные `connectors` (`required: true`), коротко, с пунктом 7.3, к которому они относятся. Нечего — «ничего».
2. Тэндер Мэн ведёт чеклист: пять звеньев × «отчитался / id / что нужно от владельца». Id каждого он знает с момента создания; id из отчёта сверяет с ним.
3. Звено молчит дольше 30 минут после создания — Тэндер Мэн пишет ему: «Пришли отчёт о готовности по последнему шагу INSTALL_BY_BOT». Молчит после второго напоминания — эскалация владельцу.

КТ: пять отчётов получены; id совпадают.

#### 7.2. Реальные id в промты

1. Тэндер Мэн подставляет id пяти звеньев в свой промт (`<id Кузнеца>`, `<id Фатимы>`, `<id Черри Пикера>`, `<id Очкарика>`, `<id Сисадмина>`).
2. Каждому звену — одно сообщение с реальными id всех ботов, которые встречаются в его `bot.placeholders`: «Id команды: Тэндер Мэн <id>, Кузнец <id>, … Замени плейсхолдеры `<id …>` в своём промте, промтах рутин и памяти, ответь «Id заменены», и результат `rg -n "<id "`».
3. Звено подтверждает. У Кузнеца останется `<id Скрипты и интеграции>` — бота с такой папкой в репозитории нет; плейсхолдер оставить, владельцу сказать в пункте d.

КТ: пять подтверждений «Id заменены»; `rg -n "<id "` пусто у всех (кроме `<id Скрипты и интеграции>`); у Фатимы — оба файла.

#### 7.3. Чеклист владельца

Тэндер Мэн сводит списки из отчётов в один чеклист и проводит его с владельцем **по одному пункту**: следующий — только после подтверждения текущего. Мелкие да/нет из списков (прежние боты остановлены, разрешения на тестовые папки `owner_steps.test_folder`/`test_card`, `old_registry`) — одной карточкой-вопросом перед пунктом a. Пункт не нужен (например, на общем box доступ уже есть) — показать владельцу и закрыть его словом.

a. **Вход rclone для Кузнеца.** Кузнец на боксе: свежий box — сначала `owner_steps.oauth_client` (секреты от владельца), затем `rclone config create gosplan …` по `owner_steps.rclone_authorize`; remote есть, но 401/`invalid_grant` или вход нужно обновить — `rclone config reconnect gosplan:`. Команда идёт в фоне, ссылку входа Кузнец открывает в браузере бокса и передаёт рабочий стол владельцу. Владелец входит аккаунтом Google, **владеющим папкой «Госзакупки»** (не аккаунтом Google Cloud Console, где создан OAuth-клиент). OAuth-клиент должен быть опубликован, In production (`kuznets/SETUP.md`, раздел 6): в Testing вход истекает через 7 дней. КТ: Кузнец — `rclone lsd gosplan:Госзакупки` показывает «Сток» и «Бланки»; Кузнец и остальные звенья доделали шаги Диска и `verification`, подтвердили Тэндер Мэну.

b. **Загрузчик на Windows-ПК владельца.** [fatima/stock_docs_fetcher/README.md](fatima/stock_docs_fetcher/README.md): владелец запускает `INSTALL.bat`, затем `STATUS.bat`. Отдельно проверять Google Drive for desktop не нужно. Кузнец сопровождает загрузчик и отвечает на вопросы. КТ: `STATUS.bat` — загрузчик работает; Кузнец или Фатима видит, что папки из «Сток» уходят в «Бланки».

c. **Коннекторы.** Только то, что требуют `connectors` в `bot.yaml`: Notion — обязательно для Сисадмина (`sysadmin/bot.yaml` → `owner_steps.connect_notion`), по желанию для Тэндер Мэна (`tender_man/bot.yaml` → `owner_steps.connect_notion`). Google Drive — у Кузнеца `required: true` (раскладка «Сток»/«Бланки»; то же видно через `rclone lsd`), у остальных звеньев необязателен (работа через rclone). Gmail ни в одном `bot.yaml` не указан — не подключать, пока владелец сам не скажет. КТ: Сисадмин доделал шаг Notion своей установки (страница «К рассмотрению», база «Тендеры»), подтвердил; Тэндер Мэн — Notion читается или записано «без Notion».

d. **Роли.** Тэндер Мэн показывает владельцу карточки-вопросы: по одной на звено — имя, `order_hint`, вход → выход, кому отчитывается (из `bot.yaml`: `bot.description`, `order_hint`, `teammates`). Варианты: «верно» / «поправить». Поправка — Тэндер Мэн передаёт звену команду владельца, звено подтверждает; в репозиторий правку вносит Кузнец только по команде владельца. Здесь же — `<id Скрипты и интеграции>`: создать такого бота или убрать. КТ: все пять карточек подтверждены.

e. **Рутины.** Каждое звено по команде Тэндер Мэна создаёт свои рутины из `routines[]` своего `bot.yaml` (имя, `cron`, промт — весь `prompt_file`), часовой пояс **Asia/Novosibirsk** (`CRON_TZ=Asia/Novosibirsk …`), время — подтверждённое владельцем (`confirm_schedule` / `confirm_routine`). Владелец одобряет каждую рутину на карточке подтверждения; звено отвечает Тэндер Мэну «Рутина <имя> создана, подтверждена». Тэндер Мэн ведёт список рутин и отмечает подтверждённые. Свои две рутины отчётов Тэндер Мэн создаёт так же — с карточкой владельца. КТ: все рутины из таблицы ниже созданы и подтверждены.

f. **Тестовый прогон.** Тэндер Мэн по очереди даёт звеньям команду на прогон на живых данных (без тестовых папок): Кузнец — статус добора / скан, загрузчик — папка «Сток» → «Бланки», Фатима — разбор, Черри Пикер — цены, Очкарик — расчёт, Сисадмин — карточка в Notion и папка в «CRM». Каждое звено отвечает Тэндер Мэну одной строкой: что взяло, что выдало, ошибки. Тэндер Мэн прогоняет свою `verification` (тестовый утренний отчёт) и даёт владельцу итоговую сводку. КТ: каждое звено отчиталось; итоговая сводка у владельца.

Рутины (пункт e) — **Asia/Novosibirsk** у всех звеньев. Часовой пояс бокса Grok Bot на расписание рутин не влияет; на него не ориентироваться.

| звено | рутина | расписание |
|---|---|---|
| Тэндер Мэн | отчёты 09:00, 21:00 | `CRON_TZ=Asia/Novosibirsk 0 9 * * *`, `… 0 21 * * *` |
| Кузнец | утренний скан 07:00; почасовая проверка добора | `CRON_TZ=Asia/Novosibirsk 0 7 * * *`, `… 0 * * * *`; только после развёртывания добора |
| Фатима | будни 08:00–19:30 каждые 30 мин | `CRON_TZ=Asia/Novosibirsk 0,30 8-19 * * 1-5` |
| Черри Пикер | :00/:30 | `CRON_TZ=Asia/Novosibirsk 0,30 * * * *` |
| Очкарик | каждые 30 мин | `CRON_TZ=Asia/Novosibirsk */30 * * * *` |
| Сисадмин | проверка «К рассмотрению» :00/:30; вечерний отчёт 21:00 | `CRON_TZ=Asia/Novosibirsk 0,30 * * * *`, `… 0 21 * * *` |

Окно Фатимы (будни 08:00–19:30) раньше было в Europe/Berlin; теперь по Новосибирску. Время утреннего скана Кузнеца и окно Фатимы подтверждает владелец.

#### 7.4. Конвейер запущен

Только после того, как закрыты 7.1, 7.2 и все пункты 7.3, конвейер считается запущенным. Итоговая сводка Тэндер Мэна владельцу — одним сообщением: созданные боты, свежий или общий box, rclone и раскладка Диска, загрузчик, коннекторы, подтверждённые роли, рутины (созданы и подтверждены), результат тестового прогона по звеньям, оставшиеся плейсхолдеры, что ещё ждёт владельца (если есть). Последняя строка: «Конвейер запущен» — или «Конвейер не запущен: <какой пункт открыт>».

## Что не коммитить

- секреты: `.env`, `rclone.conf`, `client_secret*.json`, `*.token`, OAuth client id/secret, `GOSPLAN_API_KEY`;
- реальные agent id, адреса почты, id папок Drive, id страниц Notion;
- рабочее состояние: `state/`, `logs/`, `tenders/`, `*.lock`, `*.slot`, `__pycache__/` (см. `.gitignore`); исключение — перенесённый реестр `kuznets/state/`;
- локальный `config.json` загрузчика (пути Windows-ПК владельца).

Правки — только в своей папке звена. Чужие папки не трогать.
